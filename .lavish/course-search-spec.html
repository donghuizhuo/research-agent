Feature Specification: MVP UW Course Search

A read-only UW Seattle course research agent that searches approved indexed/snapshot sources and returns source-grounded answers with citations and freshness metadata.

Created 2026-10-06 · Input: "Create the first MVP feature spec for course search."

Clarifications

Decisions recorded during the 2026-10-06 clarification session.

Q: Which UW Seattle source coverage should v1 require?
A: Official UW catalog/course descriptions and official UW department pages; no UW Time Schedule requirement for v1.
Q: Should natural-language course search be required for v1, or a stretch feature?
A: Required in v1, limited to indexed/snapshot course-source search.
Q: What should the v1 user-facing surface be?
A: Both a direct API and a simple Web UI.
Q: What snapshot refresh cadence should v1 assume?
A: Manual refresh for MVP; scheduled refresh later.

Primary User Story

As a UW Seattle course researcher, I want to search for UW Seattle courses using course codes, departments, keywords, or natural-language questions so that I can quickly find grounded course information with citations and understand whether the information is current, missing, stale, or conflicting.

Acceptance Scenarios

1Exact course-code lookup

Given a user asks for a specific course by course code, When the course exists in structured data, Then the system returns title, department, course number, credits and description when available, plus citations.

2Department / keyword search

Given a user searches by department or keyword, When matching courses exist, Then the system returns a concise ranked list with enough information to choose a course.

3Natural-language discovery

Given a user asks a natural-language course discovery question, When it can be answered from approved indexed/snapshot sources, Then the system returns a cited, ranked answer without personalized advising or unsupported inferences.

4Prerequisites

Given a user asks about prerequisites, When information is available in retrieved sources, Then the system returns it with citations and does not infer missing prerequisites.

5Quarter availability (confirmed)

Given a user asks about a quarter, When quarter-specific data is available in snapshot sources, Then the system answers with freshness and citations and notes it is not a live check.

6Quarter availability (unconfirmed)

Given a user asks about a quarter, When quarter-specific data is not available, Then the system states it cannot confirm and does not imply live-system access.

7No authoritative web fallback

Given structured retrieval misses, When web search is not explicitly requested, Then the system does not present generic web results as authoritative facts.

8Conflict surfacing

Given sources conflict, When it affects the answer, Then the system surfaces the conflict and identifies sources instead of silently choosing one.

9Sensitive data

Given a user provides sensitive student information, When it is not needed for search, Then the system avoids storing/using it and responds without requiring private data.

Edge Cases

  • Invalid or nonexistent course code.
  • Ambiguous course code or department abbreviation.
  • Course title matching multiple departments.
  • Informal terms such as "easy stats class" or "machine learning intro."
  • Requests for live enrollment, seats, registration status, instructor, or schedule when unavailable or live-only.
  • Natural-language requests needing personalized advising, official verification, or unsupported inference.
  • Information outside UW Seattle data or Seattle campus scope.
  • Follow-up questions depending on prior filters or selected courses.

Functional Requirements

Scope & search modes

  • FR-001 Limit scope to UW Seattle campus courses.
  • FR-002 Search by exact course code.
  • FR-003 Search by department.
  • FR-004 Search by keyword in title/description/indexed text.
  • FR-005 Natural-language discovery, limited to retrieval/ranking over approved sources.

Returned facts

  • FR-006 Return title, department, course number, description when available.
  • FR-007 Return credits when available.
  • FR-008 Return prerequisites/corequisites only when source-supported.
  • FR-008a No personalized advising or unsupported requirement claims from NL search.

Citations & sourcing

  • FR-009 Include citations for substantive course facts.
  • FR-010 State when a requested fact is unavailable.
  • FR-011 Prefer structured retrieval before open-ended web search.
  • FR-011a Include catalog/course descriptions and department pages in v1 coverage.
  • FR-012 Clearly label any answer using open-ended web search.

Freshness & availability

  • FR-013 Track/expose freshness metadata (quarter, year, source/index timestamp).
  • FR-014 Never claim quarter offering unless snapshot confirms it.
  • FR-015 No dependency on live UW systems or real-time availability.
  • FR-016 Communicate that live enrollment/seats/registration/schedule are out of scope for v1.

Conflicts & provenance

  • FR-017 Surface material conflicts between sources.
  • FR-018 Distinguish official vs user-provided/inferred/unofficial information.

Workflow state

  • FR-019 Maintain explicit workflow state (query, filters, courses, sources, citations, freshness, uncertainty, status).
  • FR-020 No hidden/global variables or untracked implicit memory.

Privacy & safety

  • FR-021 Avoid requesting/storing/using sensitive student information.
  • FR-022 Read-only; no enrollment, registration, payment, grade, or record actions.
  • FR-023 User-facing messages for invalid, ambiguous, missing, stale, conflicting, out-of-scope, or live-only cases.

Validation & surfaces

  • FR-024 Repeatable tests/validation for major capabilities.
  • FR-025 Expose search via both a direct API and a simple Web UI.
  • FR-026 Manual snapshot refresh for MVP; keep scheduled-refresh compatibility.
  • FR-027 Catalog/course descriptions are the primary fact source; department pages support context or clearly-structured cited facts.
  • FR-028 Control ingestion via an explicit source registry (tier, type, authority, URLs, policy, freshness).

Key Entities

Course

UW Seattle course by department and number; title, description, credits, prerequisites, metadata.

Course Source

Catalog record, course description, department page, approved snapshot, or user document.

Citation

Links an answer claim to a source: ID, URL, title, retrieval timestamp, evidence.

Freshness Metadata

Quarter, year, publication/index/retrieval timestamp.

Search Query

Current request text and interpreted filters.

Workflow State

Inspectable persisted state: query, filters, courses, sources, citations, uncertainty, status.

Assumptions

  • Limited to UW Seattle campus and publicly available or approved information.
  • Other campuses out of scope unless in approved Seattle sources.
  • Read-only; no interaction with private UW registration/advising/grade/payment/record systems.
  • Initial seed: UW CSE Catalog, Allen School, UW INFO Catalog, UW Informatics (in config/sources.yml).
  • Catalog/course descriptions are the primary fact source; department pages are supporting context unless clearly structured and cited.
  • UW Time Schedule not required for v1 unless provided as approved snapshot data.
  • Structured retrieval sources available or created before release.
  • Approved indexed/snapshot data only; no live UW dependency.
  • Manual snapshot refresh for MVP; scheduled refresh deferred.
  • Quarter-specific availability supported only when snapshot data exists.
  • Live enrollment, seats, registration status, and schedule changes out of scope for v1.
  • Open-ended web search is a fallback, not the default path.
  • First release may support a limited source set with clear coverage communication.
